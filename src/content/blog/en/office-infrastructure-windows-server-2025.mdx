When I rebuilt a manufacturer's office network, I replaced its Windows Server 2012 R2 domain with a new Windows Server 2025 environment. I was used to managing Linux servers. That experience gave me a set of questions I could bring to Windows about who gets access, how they connect, and what can be recovered when something fails.

## Local groups and domain groups

On a Linux server, I can give a group access to a directory and manage who belongs to that group. The same idea applies to Windows file shares. With Active Directory, user and computer accounts belong to a directory that can serve multiple joined machines. Domain security groups give me a way to assign access to shared resources. [Active Directory Domain Services overview](https://learn.microsoft.com/en-us/windows-server/identity/ad-ds/active-directory-domain-services) and [Active Directory security groups](https://learn.microsoft.com/en-us/windows-server/identity/ad-ds/manage/understand-security-groups).

I chose to set up a fresh forest and review which accounts and permissions to carry over. That meant rejoining computers and reviewing shared folders. It also gave me a point in the migration to confirm who actually needed access to each set of files.

## Network access and sign-in

I used a VPN for remote access. It gives an authorized computer a way to reach the office network. Windows still handles sign-in and checks what that account is allowed to do. I was used to reasoning about those steps separately on Linux, and it helped here too.

I kept monitoring on a separate Linux machine running Zabbix. That gave me a view of the Windows server from another machine.

## System files, business data, and recovery

I put Windows and the company's files on separate partitions on the same physical disk. The split gives me a clear boundary for organizing backups. A disk failure would affect both partitions, so recovery depends on backups that can be restored.

I recorded the main decisions as I went, including the choice to start with a new forest. For anyone inheriting the setup, knowing why the computers had to rejoin the domain is as useful as knowing how they were joined.
